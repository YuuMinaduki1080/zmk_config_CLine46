### 物理配列の差分をどう埋めたか

CLine46 46キー（6列×2）と LiNEA40 41キー（5列×2＋エンコーダ）で配列が違うため 1:1 コピーは不可。英字ブロックを 1:1 対応させ、段ごとに異なるオフセット（1段目 +1、2段目 +3、3段目 +5）で位置を対応付けた。CLine46 の余剰最外列（左右各1列・計6キー）と右親指の差分はユーザーが個別に決定。

### 設計判断

- **日本語入力キー（無変換・変換）を廃止**し、LiNEA40 の親指配列に揃えた
- **ホームロウモッドは採用しない**。修飾キーを専用の物理キー（左右 Shift・Win・Alt・Ctrl）に置いた。これにより LiNEA40 の `hmr_*` 6種と `tog_off` / `exit_AML` / `kp_exit_AML` の移植が丸ごと不要になった
- **`kp_exit_AML` を移植しない判断の根拠**: LiNEA40 ではホームロウモッドのタップ側に仕込まれ、「ホールド＝修飾キーなので AML 維持／タップ＝文字入力なので AML 解除」を区別していた。`excluded-positions` だけではこの区別ができないための仕掛け。修飾キーを専用の物理キーにした本構成では区別自体が不要で、`Space`(40) と `BackSpace`(41) を除外リストに入れないことで「打鍵した瞬間に解除」が素の設定で得られる
- **手動 MOUSE レイヤー(5) は定義のみ残し到達手段を設けない**（ユーザー了承済み）。LiNEA40 の `&to 5` は右親指5→4の枠不足で落とした

### Y軸反転の実装方法についての注意（将来の事故予防）

`scroller` ノードには Y 反転の候補行が**2つ**、いずれも無効状態で並んでいる。

- `//<&zip_xy_transform INPUT_TRANSFORM_Y_INVERT>` — スクロール変換の**前**に生の Y を反転する
- `//<&zip_scroll_transform INPUT_TRANSFORM_Y_INVERT>` — スクロール変換の**後**にホイール出力を反転する

**この2つは排他で使うこと。** 後日「有効化すれば反転する」と見て両方を有効にすると、反転が2回掛かって打ち消し合い、無反転に戻る。今回は前者を無効化する形で反転を実現しており、チェーン全体に Y 反転は1つも残っていない。

今回は反転の実現手段として「後者を有効化する」案も取れたが、それだと反転が2回掛かって打ち消し合う構成になり、読み手に意図が伝わらないため採らなかった。
