## 19:45 feat/auto-mouse-layer

トラックボール操作で自動的にマウス用レイヤーへ入る仕組み（オートマウスレイヤー）を実装。空きレイヤーだった `layer_5` を `AML` に転用し、`&mkp MB1` / `&mkp MB2` を右手ホームの J / L 位置にのみ配置。`CLine46_R.overlay` の `trackball_listener` に `<&zip_temp_layer 5 300>` を追加し、`require-prior-idle-ms = <200>` と修飾キー中心の `excluded-positions` を設定した。

### 設計判断

- **発動先に既存の MOUSE レイヤー(2) を使わなかった**: overlay に `//<&zip_temp_layer 2 1000>` が用意されていたが、レイヤー2 は左手が F1〜F12・右手が Ctrl+Z/Y/C/V/X/A/F に置き換わる「厚い」レイヤーで、ボール操作直後の打鍵で Ctrl+Z 等が誤発火する。同じ作者の zmk-config-LiNEA40 が「ほぼ全て `&trans` の専用 AML レイヤー」を発動先にしている構成に倣った
- **転用先を `layer_4` ではなく `layer_5` にした**: `layer_4` には `&bt BT_SEL 0`〜`4`（レイヤー3 SCROLL と重複内容）が書かれており上書きすると失われる。`layer_5` は全キー `&trans` の完全な空きレイヤー
- **時間値 300ms / 200ms は LiNEA40 の実測値を踏襲**（ユーザー判断）
- **AML の位置20 に置いた `&mo 3` を撤回して `&trans` に戻した**: AML はレイヤー5 にあり、ZMK ではレイヤー番号が大きい方が優先される。レイヤー2 を手動保持しながらボールを動かすと AML がレイヤー2 を上書きし、位置20 の `&kp UP_ARROW` が潰れる回帰があった。LiNEA40 では AML(4) が MOUSE(5)/SCROLL(6) より下にあるためこの問題が起きず、移植時に非対称が生じていた。位置34 の既存スクロールキーが AML の `&trans` を貫通するため、スクロールへの導線は失われない
- **位置20 を `excluded-positions` からも外した**: `&trans` に戻した時点で「AML の機能キーだから除外する」根拠が消えた。除外を残すと通常のタイピングで `k` を打っても AML が解除されず、直後の `j` が左クリックとして誤発火する。打鍵の安全側に倒した

## 20:50 feat/auto-mouse-layer

GitHub Actions で右手側 `CLine46_R` のビルドが `error: too many arguments to function 'zmk_keymap_layer_activate'` で失敗したため、`config/west.yml` の cormoran 製4モジュールを `revision: main` からコミット SHA に固定した。

### 原因

AML の変更が原因ではない。ZMK 本体を `v0.3-branch+dya` に固定する一方、モジュール4件を `revision: main`（動く参照）で引いていたため、モジュール側が新しい ZMK API へ追随した時点で噛み合わなくなった。本体の宣言は `int zmk_keymap_layer_activate(zmk_keymap_layer_id_t layer);`（引数1個）、モジュール `main` は引数2個で呼んでいる。フォークはフォーク元と完全同一で、フォーク元でも同じく失敗する状態だった。

左手側と `settings_reset` は成功。右手側の `.conf` にだけ `CONFIG_ZMK_RUNTIME_INPUT_PROCESSOR=y` があり当該モジュールがコンパイル対象になるため、右手側だけが落ちた。

### 設計判断

- **固定先は同梱ファーム `firmware/20260501/` がビルドされた時点（2026-05-01T10:13:32Z）の各 HEAD**。実際に動作するファームを生成した実績のある組み合わせに戻す。アンカーは firmware を追加したコミット `72f150a` の日時。取得は GitHub API の `commits?sha=main&until=<anchor>&per_page=1` で、定義上その時刻の main 先端が返る
- **ZMK 本体は上げない**。モジュール側 `main` に本体を合わせる案もあったが、キーマップ記法・Studio 連携・PMW3610 ドライバ・RGB LED ウィジェットにまで影響が及び、`west.yml` の他の固定値も全部見直しになるため却下
- **Runtime Input Processor を無効化する案も却下**。ビルドは確実に通るが、ZMK Studio からトラックボールの感度・軸を実行時に変更する機能を失う

### 未完了

- 本体・非LiPoバッテリ・PMW3610・RGB LED は依然としてブランチ参照のままで、同種の事故が本体側で起きうる。完全な再現性を狙うなら本体も SHA 固定が本筋（将来課題）
- ピンの更新手順（4件を同世代で揃えて上げる・上げたらファームも差し替える）がリポジトリ内に未記載
