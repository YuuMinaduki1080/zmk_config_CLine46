# 2026-08-07

## 03:14 tune/trackball-tracking

「トラックボールだけ追従性がやや悪い」というユーザー報告への対応。改善余地として CPI・BLE 接続間隔・センサーの RUN サンプル周期（`force-awake` による 4ms 化）の 3 つを提示し、ユーザーが前 2 つを選択した。

- `CLine46_R.overlay`: `cpi = <600>` → `<1000>`
- `CLine46_R.conf`: `CONFIG_BT_PERIPHERAL_PREF_MIN_INT` / `MAX_INT` を 12 → 6（15ms → 7.5ms）

左側は `BT_PERIPHERAL_PREF_*` を持たず、ホストと繋がるのはセントラルの右側だけなので右側のみ変更。トラックボールもセントラル側にあり、分割リンクはポインタデータの経路に含まれない。

### 見送った案

**サンプリング 4ms 化**（devicetree の `force-awake` + `force-awake-4ms-mode`）。RUN レートが倍になるうえアクティブ中はレストモードにも落ちなくなるが、電池の減りが明らかに早くなるため今回は採らなかった。CPI と接続間隔で足りなければ次の手。

### レビュー（Tier 1・1名、2ラウンド）

初回 REQUEST_CHANGES。設定値ではなくコメントの記述への指摘。

- **律速の断定が、この変更自身によって偽になりうる**。「接続間隔が報告レートの上限を決める」と書いたが、15ms（約67Hz）のときは BLE が律速でも、7.5ms（約133Hz）まで詰めるとセンサーの RUN サンプル周期（既定 8ms）のほうが律速に回る。「上限を決める要素のひとつ」に改め、RUN サンプル周期にも言及した
- 出典が「ファイル名の裸書き」で、どの fork のどの revision を見たのか追えなかった。既存ブロックと同じ「リポジトリ名 + revision + パス + 原文 + 確認日」の形式に揃えた。なお拡張子はこのドライバでは `.yml`（`zephyr/module.yml` も同様で、リポジトリとして統一されている）
- `zip_scroll_scaler の除数（現在 8）` が単数形だったが、実体は `v_scroller` と `h_scroller` の 2 か所。片方だけ直すと縦横のスクロール量が黙って食い違うため、両方と明記した

### 実機確認（要ユーザー操作）

切り分けの筋道:

- **CPI だけ効いて滑らかさが変わらない** → 接続間隔がホストに拒否されたか、センサーの 8ms が律速。前者の切り分けとして `MIN_INT=6` / `MAX_INT=12` の範囲指定を試す
- **どちらも効かない** → センサー側が律速の可能性が高く、`force-awake` + 4ms 化が次の手

そのほか、CPI 上昇に伴って前提が動く項目:

- **スクロールの分解能**。除数 8 は CPI 600 のときに決めた値で、CPI が 1.67 倍になるぶんスクロールも粗くなる（同等の体感を狙うなら除数 13 前後）。2026-08-06 から持ち越している「横の分解能 `1 8` が縦と同値でよいか」も、この変更で前提が変わった
- **AML の発動しやすさ**。微小な接触でもカウントが立ちやすくなるため、`zip_temp_layer 4 300` が意図せず発動する頻度が増える可能性がある
- **NVS 保存値との重畳**。`CONFIG_ZMK_RUNTIME_INPUT_PROCESSOR=y` で DYA Studio から感度を変更できるため、過去に Studio 側で触っていると DT の `cpi` 変更と掛け合わさる。効果が想定とずれたときの一次切り分け先
- **`CONFIG_BT_MAX_CONN=6` との併用**。右側はホスト接続に加えてスプリットのセントラルでもあり、7.5ms 固定要求はラジオ占有を増やす。複数接続時はイベント衝突でかえってジッタが出る方向にも働きうる
